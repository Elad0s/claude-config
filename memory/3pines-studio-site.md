**Yoast Premium indexables are a write-through cache — the #1 gotcha.** Writing `_yoast_wpseo_*` post meta or the `wpseo_taxonomy_meta` option directly bypasses Yoast's save hook, so `wp_yoast_indexable` keeps serving the OLD title/description on the front end even after cache purges. Always `UPDATE wp_yoast_indexable` to match (or re-save through the UI), then purge. Verify against the origin with `curl --resolve 3pines.studio:443:147.93.74.187` to rule out Cloudflare.
WP Rocket has no CLI here — purge with `wp eval 'rocket_clean_domain();'`. Elementor: `wp eval '\Elementor\Plugin::$instance->files_manager->clear_cache();'`.

**Elementor stores Hebrew in `_elementor_data` as JSON `\uXXXX` escapes, not UTF-8 bytes.** So `SELECT … WHERE meta_value LIKE '%עברית%'` and any raw string replace **silently miss everything** — you get zero hits on text that is plainly visible on the page. Always `json_decode` the tree, `array_walk_recursive` over the string values, then re-encode with `JSON_UNESCAPED_UNICODE|JSON_UNESCAPED_SLASHES`. (Re-encoding that way converts the tree to literal UTF-8, which is why a page edited once then behaves differently from its neighbours.) After any such write you must also `DELETE FROM wp_postmeta WHERE meta_key IN ('_elementor_element_cache','_elementor_css')` — `files_manager->clear_cache()` alone does NOT clear the rendered-HTML element cache, and stale text keeps being served with no cache headers to hint at it.

**Never call `wp_update_nav_menu_item()` to change one field.** It rebuilds the item from the args given and treats every omitted arg as empty — passing only `menu-item-url` wiped titles, parent relationships and menu_order across two menus here. Write `post_title` and the `_menu_item_*` meta directly instead, and back up **title, url, parent AND menu_order** before touching menus (the first backup here only had title+url, which made the repair harder than it needed to be).

**Creating WPCode snippets via WP-CLI — two blockers, both non-obvious.** (1) `wpcode_block_unauthorized_snippet_writes` (in `insert-headers-and-footers/includes/post-type.php`) hooks `wp_insert_post_empty_content` and rejects any `wpcode` insert when the current user lacks `wpcode_edit_snippets` — WP-CLI has no user, so it fails with the misleading "content, title and excerpt are empty". Run `wp --user=2 …` (elad oren, admin). (2) WPCode also filters `post_content` on save, so insert a placeholder and write the real code with `$wpdb->update`. (3) The snippet then still won't execute until you call `(new WPCode_Snippet($id))->rebuild_cache()` — deleting the `wpcode_snippets` option is NOT enough.
